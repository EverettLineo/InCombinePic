# ADR-0002：开源许可证选型

- 状态：**已接受**
- 日期：2026-10-27
- 决策人：用户（分发模式）+ 架构师（许可协议建议）

---

## 1. 背景

用户已明确本项目**开源发布**。需确定自有代码的许可证，并确保与第三方依赖的许可证兼容。

## 2. 决策

**自有代码采用 MIT License**，随仓库根目录 `LICENSE` 发布；第三方组件义务统一登记在 `THIRD_PARTY_NOTICES.md`。

## 3. 为什么选 MIT 而不是 Apache-2.0

| 维度 | MIT | Apache-2.0 | 本项目取向 |
| --- | --- | --- | --- |
| 简洁度 | 约 170 词，义务仅"保留声明" | 约 1.1 万字符，含 NOTICE、变更声明、专利条款 | MIT 显著更轻 |
| 专利授权 | 无明示条款（默认不授予） | 明示授予专利许可 + 专利诉讼反制条款 | 本项目不涉及自研专利，收益有限 |
| 与依赖兼容 | 可并入任何许可证的项目 | 与 GPLv2 不兼容（本项目无此需求） | 均无障碍 |
| 采用门槛 | 最低，便于他人二次使用 | 企业法务更熟悉，但流程更重 | 工具类产品宜降低门槛 |
| 与 GPL 的兼容 | 兼容 | 兼容（GPLv3） | 均满足 |

**结论**：本项目为个人高频使用的桌面工具，无专利布局诉求，追求"拿来就能用"。MIT 的义务最轻、兼容面最广、与全部 permissive 依赖无冲突，故选 MIT。

> 若未来出现专利风险或需要更强的主张，可在后续版本改为 Apache-2.0 —— 但**已发布的 MIT 版本不可收回**（MIT 不可撤销），届时只能双许可或在新增版本上切换。

## 4. 后果

### 必须执行

1. 仓库根目录保留 `LICENSE`（MIT 全文）。
2. 保留 `THIRD_PARTY_NOTICES.md`，并在应用内「关于 → 开源许可」页展示（T12.10）。
3. Konva 的 MIT 声明须包含 **KineticJS 与 Konva 两段版权**，不可只写 Konva。
4. Apache-2.0 组件（`image`、`fast_image_resize`）需在分发包附 NOTICE。

### 风险

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| 他人可闭源商用本项目 | MIT 允许，属预期内 | 接受：与"工具类开源"目标一致 |
| 无专利反制 | 若被专利主张，缺少防御条款 | 接受：当前无专利资产，反制条款价值低 |
| 依赖许可证漂移 | 某依赖未来改许可证 | 锁版本 + 每次升级复核 LICENSE 原件 |

## 5. 版权人署名

`LICENSE` 中版权人已确定为：

```
Copyright (c) 2026 Everett Lineo <everettlineo@gmail.com>
```

该信息同时用于 `package.json` 的 `author` 字段与 `Cargo.toml` 的 `authors` 字段，保持三处一致。后续如需变更版权人（例如改为组织名），属许可证文本变更，须新开 ADR 记录。
