# ADR-0007：模板用归一化坐标，切换按资源顺序复用实例

- 状态：**已接受**
- 日期：2026-10-30
- 决策人：架构师
- 相关：`src/domain/templates.ts`、`src/features/templates/*`、`task.md` P8

---

## 1. 背景

基线 §9 给出了 20 个模板的范围与九条切换语义，但没有定义模板的**数据表示**和**像素换算规则**。这两件事一旦定错，后续"改画布尺寸""加模板""导出"都要连带翻修。

## 2. 决策

### 决策一：模板单元格存归一化坐标（0~1），不存像素

| 方案 | 问题 |
| --- | --- |
| 按 2400×1600 写死像素 | 用户改画布尺寸（T3.5）后所有模板失效，要么重算要么禁用 |
| 每个模板存多套尺寸 | 组合爆炸，且新增画布尺寸就要重做全部模板 |
| **归一化坐标** | 任何画布尺寸下按比例换算即可；模板定义与画布解耦 |

### 决策二：像素换算按"边"取整，而不是"位置 + 尺寸"各自取整

```ts
left  = round(x * W + g/2)
right = round((x + w) * W - g/2)
w     = right - left
```

若按 `round(x*W)` 与 `round(w*W)` 分别算，相邻单元格会出现 1px 缝隙或 1px 重叠——G8 明确要求"无缝布局下无缝隙与半像素描边"。按边算则相邻两格共用同一个取整后的边界值，天然对齐。

### 决策三：切换模板按资源库当前顺序，一图一格，复用最早实例

对应基线 §9.4 的九条，实现落点：

| 规则 | 实现 |
| --- | --- |
| 按资源库顺序匹配 | `order` 由 `libraryStore.getSorted()` 给出（受当前排序模式影响） |
| 一个资源多个实例 → 用最早的 | 按 `createdSeq` 升序取第一个，其余不进入新布局 |
| 同路径多条目各自独立 | 分组键是 `libraryItemId`（条目 id），不是路径 |
| 不重复创建 | 已有实例的条目直接复用，不新建 |
| 资源不够 → 空格留空 | 循环上限是 `min(格子数, 资源数)` |
| 未使用的实例移出画布 | 新布局只包含被复用的实例，其余丢弃（资源库条目不动） |
| 图像级属性保留 | 复用只改 `frame`，`crop/rotation/flip/opacity/border/cornerRadius` 原样带过去 |
| 原子撤销 | 整个切换是一次 `commit`，快照模型天然满足 |

**代价**：被移出画布的实例，其编辑（裁剪、位置）会随实例一起消失，撤销可恢复。这是基线明确要求的语义，不是取舍。

### 决策四：`contain`（完整显示）只缩小不裁切

`coverCrop` 取 `max` 缩放并返回二次裁切后的 crop；`containCrop` 取 `min` 缩放且**原样返回 crop**，剩余空间露出画布背景。

两条路径都只读 `crop`，不写回——否则切换一次适配模式就会永久改变用户的裁剪数据。

### 决策五：填空不确认、替换要确认

- 点空白格 → 选图 → 直接放入（可撤销，无破坏性）；
- 替换已有图片 → 原生确认框 → 确认后执行，**裁剪按新图重置**（新图尺寸不同，旧裁剪坐标无意义）。

基线只要求"替换必须确认"，填空属于新增能力，按"可撤销即可逆"的原则不额外加确认，避免每次填格都弹窗。

## 3. 后果

- 20 个模板的"铺满、不重叠、不越界"由 43 项用例覆盖（含逐个模板参数化验收）。
- 画布尺寸变化后模板自动适配，不需要重算或迁移数据。
- 空白单元格的占位与点击判定都从同一份 `templateFrames` 派生，不存在"画在这里、判在那里"的错位。
- 导出（P10）必须复用 `templateFrames` 与 `containCrop/coverCrop` 同一套几何。
